
# LLM Comparison Platform

A full-stack web application that allows users to compare responses from two different Large Language Models (LLMs), vote for the better response, and track model performance through a leaderboard and comparison history.

This project was developed as a technical assignment for Dr. Tian.

## Features

- Submit a text prompt to two different LLM providers.
- Display AI-generated responses side by side.
- Vote for the preferred response.
- Prevent duplicate votes for the same comparison.
- View a leaderboard showing model performance.
- View previous comparisons and voting history.
- Preserve comparison history across browser sessions and local server restarts.

## Technology Stack

- Frontend: Next.js, React, TypeScript, CSS
- Backend: Next.js API Routes
- LLM Provider A: GroqCloud
- LLM Provider B: Cerebras Inference
- Storage: Local JSON file
- Version Control: Git and GitHub

## Prerequisites

Before running the application, install:

- Node.js 20 or later
- npm
- A Groq API key
- A Cerebras API key

API keys can be obtained from:

Groq: https://console.groq.com/keys

Cerebras: https://cloud.cerebras.ai/

Both providers offer free-tier API access, subject to their usage limits and model availability.

## Installation

1. Clone the GitHub repository:

   git clone <repository-url>

2. Navigate to the project directory:

   cd llm-comparison-platform

3. Install dependencies:

   npm install

4. Create a local environment file by copying `.env.example` to `.env.local`.

5. Add your API keys to `.env.local`:

   GROQ_API_KEY=your_groq_api_key
   CEREBRAS_API_KEY=your_cerebras_api_key

   MODEL_A=openai/gpt-oss-20b
   MODEL_B=gpt-oss-120b

6. Start the development server:

   npm run dev

7. Open the application:

   http://localhost:3000

## How to Use

1. Enter a prompt in the input field.
2. Click "Compare Models".
3. View the responses generated by Groq and Cerebras.
4. Vote for the response you prefer.
5. Open the Leaderboard section to view model performance.
6. Open the History section to review previous comparisons and votes.

## Testing

The application was manually tested using the following steps:

1. Submitted a prompt and verified that both LLM providers returned responses.
2. Confirmed that both responses appeared side by side.
3. Submitted a vote and verified that it was recorded.
4. Checked that the leaderboard reflected the vote.
5. Verified that the previous prompt and vote appeared in History.
6. Closed and reopened the browser and verified that history remained available.
7. Restarted the local development server and confirmed that history persisted.
8. Ran `npm run build` and confirmed successful compilation, TypeScript validation, and linting.

## Architecture

The frontend sends comparison requests to the Next.js backend.

The backend calls the Groq and Cerebras APIs concurrently using Promise.all(), then stores the completed comparison.

Voting results are saved in local JSON storage.

The leaderboard calculates model performance using stored votes.

A browser-specific visitor ID is used to retrieve the user's previous comparisons without requiring account registration.

## Limitations and Future Improvements

This implementation uses local JSON storage and anonymous browser identifiers to keep the architecture simple.

For production deployment, improvements would include:

- Replacing local JSON storage with a hosted database.
- Adding secure user authentication.
- Implementing API rate limiting.
- Adding more comprehensive automated tests.
- Improving error handling and monitoring.

Local JSON storage is not suitable for reliable persistence on Vercel. A hosted database is required before deploying a version that preserves voting history reliably.
